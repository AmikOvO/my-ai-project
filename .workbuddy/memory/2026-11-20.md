# 2026-11-20

## 项目 two（my-ai-project）部署上线

**架构变更**：原计划「GitHub 构建 → 阿里云 ACR → ECS 拉取」被弃用，因为 GitHub Runner（境外）`docker login` ACR 恒 403。
实测证据：阿里云鉴权接口返回 200 + access_token（凭证有效），registry 侧 403 → 属网络层/访问控制拦截，与密码无关（密码错是 401）。
**现方案**：push main → Actions 打包源码 scp 到 ECS → 服务器本地 `docker compose build/up`（阿里云 PyPI 源 + npmmirror）。

**服务器事实**：47.95.28.173，deployer 用户，`/opt/app`，2核1.7G，无 swap，无免密 sudo，docker 29.10 + compose v5.8。
SSH 私钥在本机 `~/.ssh/github_action_key`，可直接 ssh 运维。

**踩坑（按出现顺序，都已在仓库修复）**
1. `backend/requirements.txt` 是 UTF-16LE → pip 必失败
2. requirements 含 `pywin32`（Windows 专属）→ Linux 构建失败
3. 前端 baseURL 写死 `127.0.0.1:8000`、timeout 5s
4. 前端 Dockerfile node:18 与 vite 8 / engines ^22.18 不兼容
5. 缺 .dockerignore → Windows node_modules 污染容器
6. 后端 Dockerfile python:3.10 与 3.13 依赖不符
7. `rag_source/` 被 gitignore；chroma_db 不在镜像 → RAG 首次查询 500
8. chromadb 需联网下载 ONNX 模型（国内不通）→ 把本地 `~/.cache/chroma/onnx_models/all-MiniLM-L6-v2` scp 到 `/opt/app/chroma-model`，只读卷挂载
9. `env_file: .env` 强依赖 + `/opt/app` 原本为空
10. CI 里 `tar` 归档写在仓库目录内 → 读到自己退出码 1
11. 构建 `command_timeout 30m` 不够（2核首次约 25-30 分钟）

**结果**：http://47.95.28.173 已上线，两容器 healthy，登录 + RAG 建库正常（4 个文本块）。
**唯一遗留**：DeepSeek 账户 402 余额不足；换 Key 只需在 `/opt/app/.env` 写 `DEEPSEEK_API_KEY=` 后 `up -d`，无需重建镜像。

**两条流水线**：`deploy-on-ecs.yml`（push 自动，当前生效）、`deploy.yml`（ACR 方案，改为仅手动触发，待访问控制放开后启用）、`acr-diagnose.yml`（手动诊断）。
